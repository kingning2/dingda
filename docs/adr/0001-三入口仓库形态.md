# ADR-0001：三入口仓库形态

状态：采纳 · 日期：2025-09（monorepo 脚手架，f5b85d94）

## 背景

叮答是一个桌面端 Web 产品 + 客户端 + Python 服务端的三体应用：浏览器里跑 React，
桌面壳要起停 Python Server 并注入 OS 能力，Server 是唯一状态持有方。三种生态各有
自己的包管理与依赖树，塞进同一套包管理器（比如全用 pnpm）会让锁文件、构建缓存和
CI 缓存全部互相污染。

## 决策

仓库按入口拆三个工作区，互不干涉：

| 入口 | 目录 | 工作区 | 命令 |
|------|------|--------|------|
| Web 应用 | `apps/web/` + `packages/` | pnpm | `pnpm dev`（Vite :1420） |
| Python Server | `packages-py/` | uv | `uv run python -m api`（:8787） |
| 桌面客户端 | `packages-rs/client/` | Cargo | `pnpm tauri dev` |

- `pnpm-workspace.yaml` 的 glob 不写 `packages*`，避免把 `packages-rs` 当 JS 包扫。
- Tauri CLI 只认 `<cwd>/src-tauri`，故 `pnpm tauri` 经 `scripts/tauri.mjs` 注入
  `TAURI_APP_PATH` 指向 `packages-rs/client`，禁止直接 `pnpm exec tauri`。

## 后果

- 三套锁文件（`pnpm-lock.yaml` / `uv.lock` / `Cargo.lock`）各自冻结，CI 分 job 缓存。
- 成员包边界与依赖方向由 `packages/README.md`、`packages-rs/README.md` 约定。
- 跨生态联调（桌面壳 ↔ Server ↔ Web）靠 Tauri 资源打包约定，见 `desktop-release.yml`。
